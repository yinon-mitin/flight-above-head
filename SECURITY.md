# Security policy

## Supported version

Security fixes are applied to the latest commit on `main`.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, exposed credential, or private-data leak.

Instead, contact the repository owner privately through the GitHub profile for [@yinon-mitin](https://github.com/yinon-mitin). Include:

- a concise description of the issue;
- affected file, component, or commit when known;
- safe reproduction steps;
- potential impact; and
- any proposed mitigation.

Do not include Wi-Fi credentials, exact installation coordinates, access tokens, private keys, or sensitive logs in the report.

## Scope

Relevant reports include credential handling, configuration privacy, TLS validation, GitHub Actions supply-chain issues, and firmware behavior that could expose private data or undermine alert visibility.

This project is an informational display, not a certified warning system. Availability or data-quality reports for third-party feeds are welcome, but they may be operational issues rather than security vulnerabilities.
